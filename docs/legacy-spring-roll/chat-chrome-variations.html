The front page is the history

No rail section, no popover, no standing list beside the transcript. /chat becomes the home for conversations — the same shape as Tasks and Runs: an index of documents, open one to read it. The composer on the front page is "new conversation": type, and you're in a fresh one. History stops being chrome and becomes a page.

Why this fits the ethos. Every other section already works this way — nothing new to learn, nothing raw on permanent display. Chrome appears only as the two moments you need it: arriving (recent conversations under the composer) and leaving (the letterhead breadcrumb). The one-column rule comes back intact.

01The front door — /chat

Composer up top where a launcher belongs, recent conversations beneath it, quietly. Typing starts a new conversation; clicking a row resumes one. "Show all" unfolds the full history in place — the expansion you asked for, no separate archive page.

04Build notes

Routing. /chat renders the index state (composer + history list); sending the first message creates the session and patches to /chat/:id — the code already does exactly this, only the empty-state visuals change.

Index page. Composer ~17% down, model-only status line, "Earlier" list from Sessions.list/1 (name · last-line snippet · age), first ~8 with "Show all N conversations" expanding in place.

Letterhead. The :head slot becomes Chat › {session name} on conversation routes, CHAT linking to /chat. Session name refreshes when Pi names the session after the first exchange.

Deletions. The right context rail, the History popover, the mobile verbs row, and every "New conversation" button — the front page replaces all of them, on every screen size.
