Chat dock study · berth chunk 5 + chunk 2 · 2026-07-24

The berth becomes a dock: the conversation stays where you are.

Today the berth band is a doorway — type on any page and you are teleported to /chat, losing the page you were asking about. This study makes chat a standing part of every page: open by default, minimizable to the band, aware of the task or run it sits under, speaking one message language, with the model and the meter in view.

Four decisions, one per section: the shape of the dock (A–D), the message language to standardize on (M1–M3), where the instruments live — model picker, tokens in/out, cost (I1–I3), and how the context envelope shows itself (E1–E3). The recommendation is B+D · M2 · I2 · E1, assembled in “The pick.”

§0Today: a band that leaves

What ships on feature/rail-masthead: every page ends in the berth band, but Enter stashes the message in sessionStorage and navigates to /chat. The conversation and the page never share a screen. The model picker and the usage line exist only on /chat.

§1The shape of the dock

Where does the thread live when you talk from a page? All four shapes keep the berth’s settled grammar — hairline above, band aligned to the page’s max-w-4xl column, ❯ mark — and differ only in how the conversation occupies the room.

AThe bloom — closed until you speak

The band stays a one-line strip; the thread blooms above it on focus or first send, and folds when you click back into the page.

§4The context envelope

The dock must know where it is — on /tasks it should see the list, on a task it should see that task, on a run its transcript. The machinery is chunk 2 (a per-LiveView page_context assign the session prepends to the first turn). The design question: how does that knowledge show, so it is never invisible magic?

§6Ledger — what this asks of the code

  • The berth slot grows a thread. Layouts.app’s berth footer hosts a dock region above the band; the chat session logic in ChatLive.Index (writer, streams, usage, proposals) extracts into a component/hook both the dock and /chat mount. The sessionStorage handoff and its front-door guard retire on desktop — the dock talks to its own session in place.
  • Default open, remembered minimize. Open with the thread visible wherever a live conversation exists; band-only when none does. Minimize state persists like the rail (localStorage, applied before paint).
  • One grammar, two densities. The transcript component takes a dense flag; /chat renders it bare. No second message vocabulary anywhere.
  • Instruments in the head. Usage totals and the model picker move into the dock head on pages; /chat keeps its split status line. Per-turn receipts as hover titles are a cheap follow-on.
  • Chunk 2 rides along. page_context assign per LiveView (task_id / run_id / folder), the chip in the composer, the stamp on the first turn. This study makes chunk 2’s UI decisions, so implementing chunk 5 without it would ship a dock that doesn’t know where it is — do them together.
  • Open questions for picks: does the dock stay open across page navigations mid-conversation (proposed: yes, it follows you)? Does minimizing while streaming surface anything (proposed: the band’s ❯ pulses run-orange until read)? Dock height — fixed max like the mocks, or user-draggable?
