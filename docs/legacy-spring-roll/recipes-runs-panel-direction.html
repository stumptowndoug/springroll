Direction — list + week + panel

converging: keeps the current row and strip, adds a panel and a week

Everything below assumes your calls: Week A without chips, the current list and strip kept for Recipes, no month view, Runs stays close to what it is with an inbox flavour, and a right panel on both.

Two things I resolved rather than left open:
Group
Chips are gone. Folder becomes a page-level scope — the mechanism already in the code (?folder=, TaskFolders.resolve_selection/2). Scope shows as a breadcrumb above the title and every view inherits it, so the calendar needs no group control of its own. In the flat list, folders remain quiet section headings.
Panel vs berth
The panel sits inside the content area; the berth keeps the full width beneath it. Selecting something sets the berth's context — the envelope reads AssessorSearch · today 2:31 PM — so the panel feeds the chat instead of competing with it.

Why scope beats chips: a chip row is a control that only exists on one view and has to be re-learned there. Folder scope already exists, already has a URL, already survives a refresh, and applies identically to List and Week. The breadcrumb doubles as the way back out.

The frame above shows both at once — solid past, dashed future — which is the useful version, but it means the Week view is really the Runs data with the schedule projected forward.
