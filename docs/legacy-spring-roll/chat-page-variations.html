Design study · Chat v1 page · rev. 2

Read like Pi's own terminal, not a chat app.

The first pass borrowed chat-app furniture — tonal bubbles, a floating action rail, a rounded composer card. This pass drops all of it. The transcript is set in the app's existing mono, a ❯ marks a user line instead of a background well, hidden work collapses to one dim status line, and the composer reads like a prompt, not a text-message box.

Still true from the plan: Pi owns the session; this is a quiet projection of it plus one explicit door — Create task from this — back into Tasks. No avatars, no model picker, no permanent thread list. The only new idea here is the register: monospace, prompt-glyph, terminal-flavored — closer to what actually streams out of the pinned Pi RPC process.

A · BareThe terminal is the page

No panel, no fill. The running head and the earned composer border are the only structure — the rest is space, exactly like the rest of the app already differentiates chrome with ground, not strokes.

B · RecessedOne tonal ground for the whole session

The transcript and composer share a single bg-2 well instead of a border, so it still reads as "one terminal" without adding a stroke the house style avoids.

Two moments in the same register

Independent of Bare vs Recessed, these read the same everywhere.

History as a popover

A borderless mono ledger, not a page. Each row is a Pi session name (or clipped first message) and a relative time — nothing else. Opening it doesn't navigate; picking a row patches the URL to /chat/:session_id.

Create task from this

Appears only after a completed exchange. Reads like a terminal confirming a plan before it runs a command — normalized facts, not assistant prose, and nothing is written until the last line is chosen.

What every variation must keep true

The plan's rules, read in the terminal register.

01Glyph, not bubble

A user turn is marked by one ❯ in accent color, not a background well. Assistant text sits in the same plain mono, unmarked — closest to real stdout.

02One hidden-work line

Thinking, tool calls, and lifecycle events collapse into one dim status line — ● working, ● searching the web — with a live cursor, never a collapsible trace.

03Words, not icons

History, New conversation, and Create task from this stay words, set in the same mono as the transcript so the action row reads like part of the same terminal, not a toolbar bolted on top.

04History is temporary

It opens as a popover over the current session, never a permanent thread list competing with Tasks/Runs in the nav.

0540px minimum, no hover-only control

The composer row and its controls stay ≥40px tall in practice; nothing depends on hover or a tooltip to be discoverable on mobile.

Recommendation

Ship A, Bare REPL

It costs nothing extra: no panel, no fill, just the running head, the transcript, and the one earned composer border the rest of the app already uses for "fillable." It reads as the quietest possible option and matches the house instinct to differentiate with ground and space before ever reaching for a stroke.

Keep B in reserve

If a session ever needs to read as visually distinct from the surrounding page — for example if Chat gains a second, unrelated panel later — the recessed bg-2 pane is the fallback that still avoids a border. Not needed for v1.

Net: Bare REPL transcript and composer, mono action row above it, popover history, and the terminal-style proposal block from the Moments section above.
