Chat output — four revamps

One turn, rendered five ways: today's transcript, then four directions. Same ask, same 18-step tool loop, same answer. Left pane is the turn while it runs; right pane is the turn once it is history — which is the state a thread spends 99% of its life in.

The loop is permanent18 pills sit between ask and answer forever. Runs already collapse to Activity · N steps; chat never adopted it.
Pills report input, never result“Search web · done” says the state twice and the outcome never. Failure and success differ only by dot color.
Three altitudes, one gap12px ticks, 18px approval cards, and letter prose all stack at 22px with nothing marking which one wants you.
Turn boundaries are invisibleModel · tokens · cost is 10px mono under each message; with interleaved run letters you can't see what to retry.

True in every option

  • Kill “· done”. The dot is the state. Steps carry a result instead — 1,204 rows, 8 results, 12 kB, or the actual error text in danger color.
  • Product language, not tool ids. tool-call_read_connection_tool → “Neon · run_sql”; fetch_public_url → “Fetch neon.tech”. The host already knows the connection name.
  • One renderer. Streaming and completed text both mount through Rollmark, so the answer doesn't reflow the moment the stream closes.
  • One progress signal. “Springroll is working…” and the in-flight pill are the same fact reported twice; keep whichever the option owns.
  • Detail wraps or expands. Today's white-space: nowrap mono line cuts the SQL mid-token with no way to see the rest — clamp to two lines, expand on click.
  • Cost lives on the turn, not the message. Peak-step tokens beside billed cumulative, which the TODO already wants.
