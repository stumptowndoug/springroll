A · Ledger rows — settings are a list, not a stack of cards

Same container grammar you already have for runs (one surface card per group, hairline rows inside), applied to settings. A row is 52px instead of 92px: title and current value on one baseline, the explanation as one truncated muted line. Providers become rows too — the 180px card with a 3em blurb block becomes a 44px row with a mark, a name, and its footer status inline; the action only appears on hover, so a connected provider is a fact, not a form.

  • Wins: ~70% shorter page; every setting scannable in one column; the value is always visible without opening anything.
  • Costs: provider blurbs get truncated; loses the "each provider is a card you own" feeling from the Integrations grammar.
  • Keep cards for themes only — they are the one setting that has to be seen, not read.

B · Section rail — one domain on screen at a time

The page stops being a scroll of everything. A sticky 176px rail lists the four domains with a live status dot; the pane on the right shows only that domain, so no single view is taller than about a screen and a half. Card grammar survives intact — provider cards just drop to a 2-up single-line shape.

  • Wins: nothing is compressed or truncated; there is room to grow (more capabilities, connectors) without making the page longer; rail dots surface "Google not connected" without opening the section.
  • Costs: a second navigation level inside a page that already lives behind a nav item; deep-linking (#web-research) needs to select a pane.

C · Overview + drill-in — the page answers before it asks

Settings opens as five summary tiles that fit one screen. Each tile states its current answer ("Claude Sonnet 5 · 20 turns · $1.00") and expands in place to the full controls; the closed state is the thing you actually came to check. Only one tile needs to be open at a time.

  • Wins: the shortest resting state of the four, and the only one where the page is readable as a status report; expansion keeps full card grammar inside, so nothing is truncated.
  • Costs: one click to change anything; needs a rule for which tile is open on arrival (none, or the one you deep-linked).
  • Try it — the tiles below open.

D · Dense field grid — keep the cards, stop stacking them

Nothing is hidden and nothing collapses; the page just stops being one column. Each setting is a small labelled field card in a 2-up grid, providers are 4-up chips (mark, name, status dot) that open the existing connect popover, and the theme picker becomes one row of swatches with "Browse" for the full rails.

  • Wins: smallest change to what you have — same cards, same popovers, mostly a layout swap; no new interaction to learn; roughly halves the page.
  • Costs: two columns means no reading order, so grouping has to carry the meaning; description text has to shrink to a hint or move into the popover.
