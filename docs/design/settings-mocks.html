Today — baseline

The real page: 1 long scroll, 5 top-level sections, 12 cards at min-height 180px, 7 role rows at min-height 92px, 4 theme rails at 232×128+ each, 48px between sections and 112px below the page.

Where the height goes

  • Theme rails ≈ 25% of the page (18 previews, 4 groups)
  • Provider cards ≈ 30% (8 cards, 3-line blurb each)
  • Role rows ≈ 25% (92px min-height each, 2-line helper)
  • Gaps + display title + intro ≈ 20%

Notes

  • Every section repeats a label, then a heading, then a card
  • Nothing is hidden, so first-time setup and daily use cost the same scroll
  • Card aesthetic is fine — the padding and the reserved blurb line are not

Option 1 — Tighten in place

Same information architecture, no new navigation. Cards stay, but every metric that reserves space gets removed and providers become roster rows inside one card. Nothing is hidden — you just stop paying 92px per setting.

Mechanics

  • Role rows min-height 92 → 54; helper text collapses to a ? tooltip (or a one-line muted hint)
  • Provider cards → one Providers card with 2-column roster rows (logo, name, kind chip, status, action)
  • Blurbs dropped from the row — the kind chip already says what it is
  • Group headings become slim labels above the roster, not h2 + p blocks
  • Themes become a wrap flow of 18 pills with real color dots; group labels stay inline
  • Theme + text size merge into one Appearance card
  • Section gap 48 → 26, page bottom 112 → 48, title at 2.25rem

Trade-offs

  • Tooltips hide text some people need — keep the sentence in aria-describedby
  • Loses the visual weight that made providers feel like "places"
  • Cheapest change: mostly CSS, one new row component

Option 2 — Panels (one question at a time)

Keep the cards almost as they are and stop stacking them: four panels behind a segmented control, deep-linked with ?panel=providers so a section is still shareable and back-button safe.

Mechanics

  • Segmented control replaces the vertical section sequence
  • Counts on each tab (5/8, 1/3) so state is scannable without visiting
  • Panel content keeps today's cards — only the visible subset shrinks
  • Provider connect popover stays anchored where it is today

Trade-offs

  • Settings you didn't open are invisible — bad for discovery, fine for changes
  • Tab bar competes with the titlebar nav; two levels of tabs on one screen
  • Search ("which panel is the turn limit in?") still unsolved

Option 3 — Side rail + narrow body

The page keeps its single scroll, but a sticky rail answers "where am I / what still needs a key" and the body narrows to 760px so rows stop stretching. Connected counts move into the rail — the scroll becomes navigation instead of discovery.

Mechanics

  • Rail items are scroll-spy anchors with counts, warning dots where setup is incomplete
  • Body column drops to --page-narrow; provider grid goes 2-up so card height stops being wasted on width
  • Long guardrail prose moves under a slim caption instead of a 92px row
  • Themes: single rail, 96px mini previews (color is the point, not the fake inbox)

Trade-offs

  • Least aggressive on height (rail adds chrome), best on perceived length
  • Sets up a pattern the rest of the app doesn't use yet
  • Rail needs a mobile collapse rule

Option 4 — Overview grid + progressive disclosure

What you look at every day is six values, not six sections. Show a dense key/value overview you can edit in place, and put the setup work (keys, credits, 18 themes) inside disclosures that remember their open state.

Mechanics

  • Overview card is a 4-up dl grid: label + value, click a value to change it
  • Collapsed disclosures carry their current values in the summary line, so nothing is hidden while closed
  • Warning dot on any collapsed group that needs action (3 providers need keys)
  • Theme picks are one pill row; preview size stops eating 128px per theme

Trade-offs

  • Two states to design and test (collapsed summary must stay truthful)
  • Least discoverable for first run — pair with a "Set up" mode that opens everything
  • Deepest cut, biggest refactor: the values need a real editor affordance
