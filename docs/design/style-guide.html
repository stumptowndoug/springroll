ShrimpRoll · Style guide v3

Colors, type, one button, status

Stripped to the essentials. A theme is a terminal color scheme — ten values, the shape of anything on terminalcolors.com — and every base color now shows its derived values inline, so the whole system reads as input → output. One button. Status runs on derived cyan (the green swap is a one-line change).

Colors

base (from theme) → derived (computed, never in a theme file)

Text is always fg or muted; hues appear only as dots, tint grounds, and the accent on links. Tints are each hue mixed into bg — which is why any terminal scheme, light or dark, arrives with a complete working set.

Type

display 800 / −0.03em · body Inter · mono = telemetry
What happened. Body 14/1.6 07:00 · $0.004 · 41s Section label

Times, costs, tokens, durations are always mono and always muted — telemetry whispers. Everything else is Inter. One display headline per page, nothing else oversized.

Button

one kind: fg ground, bg text — correct in every theme
New task Disabled Review →

Primary pill for the action, accent text for everything lighter. That's the whole vocabulary for now.

Status

ok = cyan · quiet dots by default · two loud states
Quiet — dot + muted text
Sent Nothing new Did not finish Paused
Loud — the only tinted pills
Running Needs you

Good outcomes read as cyan (--ok: var(--cyan)). If green ends up feeling better, it's a one-line swap — nothing else references the hue directly.

Theme file format — the shape of every scheme on terminalcolors.com, shown live as you switch:


  
/* derivation rules — app CSS, identical for every theme */

tint(hue) = mix(hue 15–32%, bg)          ring = mix(accent 45%, bg)
ok = cyan                                primary button = fg ground / bg text
